## 2. File-by-File Proposed Changes Inventory

### 2.1 New Files Proposed (Phase A)
1. **`src/server/jwt-secret.ts`** — Strict `SESSION_JWT_SECRET` loader (production fail-fast, minimum entropy check, legacy default denylist, optional `SESSION_JWT_SECRET_PREVIOUS` verification ring).
2. **`src/server/firebase-admin.ts`** — Singleton `firebase-admin` initializer (ADC + `projectId`, zero static key files), `verifyFirebaseIdToken()`, and error-code normalization (`401`/`403`).
3. **`src/server/auth-middleware.ts`** — Single trusted backend authentication & authorization middleware (`requireAuth`, `optionalAuth`, `enforceTenantScope`, `enforceBranchScope`, `requireCapability`, `securityAuditLog`, SSE stream ticket signer/verifier).
4. **`src/lib/auth-fetch.ts`** — Shared client-side fetch wrapper attaching `Authorization: Bearer <token>` (from session token or Firebase ID token), removing `'x-user-id'`, and dispatching clean `401` re-authentication event without losing offline state.
5. **`src/server/__tests__/phase-a-security.test.ts`** — Comprehensive automated security test suite covering all 14 mandatory Phase A scenarios.

### 2.2 Existing Backend Files Proposed for Surgical Edits (Zero DB Schema Changes)
1. **`package.json`** — Add `"firebase-admin"` to `dependencies` (single new runtime dependency).
2. **`.env.example`** — Document variable names only (`SESSION_JWT_SECRET`, `SESSION_JWT_SECRET_PREVIOUS`, `FIREBASE_PROJECT_ID`, `FIREBASE_CHECK_REVOKED`, `ALLOWED_ORIGINS`) with placeholder descriptions (zero real values).
3. **`server.ts`** — Protect `/api/store-sync`, `/api/transactions`, `/api/products*`, `/api/currencies*`, `/api/exchange-rates*`, `/api/convert`; remove `allowInternalDefaultIfNoHeader: true`; remove `resolveRequestCompanyScope` and client-header `isPracticeModeRequest` trust; tighten CORS `Access-Control-Allow-Headers` (stop advertising `x-user-id` / `x-user-role` in production mode).
4. **`src/server/release-onboarding.service.ts`** — Wire `jwt-secret.ts` into `signSessionJwt`/`verifySessionJwt`; add optional `firebaseUid` field on `StoredUserRecord`; add `resolveUserForFirebaseToken()` & `POST /api/auth/firebase-exchange`; remove `x-user-id`/`query.userId`/`body.userId` & `allowUnauthenticatedDefaultRead` & `|| state.companies[0]`; redact company enumeration on unauthenticated `GET /api/onboarding/status`; require `requireAuth` + `COMPANY_OWNER` on `POST /api/onboarding/factory-reset`.
5. **`src/server/shared-store-sync.ts`** — Fail closed in `filterByCompanyScope` (empty `companyId` → `[]`; require strict `item.companyId === companyId`); enforce authoritative `companyId` override in `tagWithCompanyScope`.
6. **`src/server/lan-sync.service.ts`** — Protect `/info`, `/state`, `/push` with `requireAuth` + `enforceTenantScope`; add `POST /stream-ticket`; validate `?ticket=` on `/stream`; remove `'comp-clean-store'` default fallback and cross-company SSE broadcast leakage.
7. **`src/server/backup-restore.service.ts`** — Delete `resolveBackupActorOrLocalStore`; remove `'local-owner-bypass'` and `'unassigned-operator'` re-auth bypasses; protect all `/api/backups/*` routes with `requireAuth` + `requireCapability` + `assertActorCompanyMatch`; tighten `collectServerCompanyPayload` to strict `companyId` equality; enforce first-run-only gate on `restore-new-company`.
8. **`src/analytics/analytics.routes.ts`** — Replace `parseUserContextFromReq` with `requireAuth`; remove `x-user-id`/`query.userId`/`body.userId`; pass `req.auth.companyId` into `loadServerAnalyticsDataset` everywhere (including line 988); enforce company scoping on `POST /overview` snapshots and all `/lifecycle/*` routes.
9. **`src/analytics/analytics.repository.ts`** — Key `cachedSnapshot` by `companyId` (`Map`); enforce strict `companyId` filtering on all returned collections (`products`, `transactions`, `returns`, `purchases`, `customers`, `stockMovements`, `users`, `branches`, `unmetDemandRequests`) without modifying any calculation, forecast, or schema.
10. **`src/analytics/intelligence.lifecycle.ts`** — Scope lifecycle item lookup, history, and transitions by `companyId` so items cannot be accessed or mutated across tenants.
